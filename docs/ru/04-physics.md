# 4. Физика персонажей

Кривая задаёт персонажу цель, а позиция догоняет её как груз на демпфированной пружине. Отсюда инерция, крен в поворотах и вращение. В шейдер уходит позиция из физики, а не значение кривой.

## Записи

Четыре записи по 64 байта; физика есть только у персонажей, у камеры и босса её нет.

| Адрес | Персонаж | Трек позиции | Параметры `(spinDivisor, stiffness, damping, bankGain)` |
|---|---|---|---|
| `0x0b17bdf0` | main | `uMainCharacterPos` | `(0.25, 3.5, 2, 320)` |
| `0x0b17be30` | evil1 | `uEvilCharacterPos1` | `(1, 1.5, 2, 400)` |
| `0x0b17be70` | evil2 | `uEvilCharacterPos2` | `(1, 2.5, 1, 400)` |
| `0x0b17beb0` | evil3 | `uEvilCharacterPos3` — не используется ни одной строкой | `(1, 1.5, 1, 400)` |

Босс — не четвёртая запись, а обычная кривая `uEolBossPosition`.

| Смещение | Поле |
|---|---|
| `+0x00` | позиция P, SIMD `[0, z, y, x]` |
| `+0x10` | скорость V, SIMD `[0, z, y, x]` |
| `+0x20..+0x2c` | `spinDivisor`, `stiffness`, `damping`, `bankGain` |
| `+0x30` / `+0x34` / `+0x38` | spin / yaw / roll |
| `+0x3c` | не используется |

Всё, кроме параметров, на старте равно нулю.

## Когда вызывается

Физика вызывается сразу после вычисления трека позиции, внутри цикла по дескрипторам строки.

1. Дескриптор — трек позиции персонажа (поиск по строковому имени, `0x407f9c..0x408023`).
2. Цель `T` = кривая в `localBeat`; опережение `L` = кривая в `f32(localBeat + 0.01)`.
3. Вызов физики; она перезаписывает `T` своей позицией.
4. После всех дескрипторов загружаются uniform. Повороты (`uMainCharacterRotation`, `uEvilCharacterRotation1..3`) загружаются всегда из текущих записей.

Особенности:
- Опережение берётся в **битах**, а `dt` — в **секундах**, без пересчёта.
- Если в строке нет трека, запись не меняется. При смене сцены сброса нет.
- В кадре 0 и при инициализации `dt = 0`: функция сразу выходит, в шейдер уходит сырая кривая.

## Алгоритм (`0x406019`)

ABI: `ECX` — запись, `XMM1.low` — dt, `[esp+4]` — цель T (перезаписывается), `[esp+8]` — опережение L, `ret 8`. Все операции — SSE float32 с округлением после каждой, без FMA.

```
if dt == +0 or dt == -0: return             // NaN не выходит

E    = T - P
err2 = (Ex·Ex + Ey·Ey) + Ez·Ez
if err2 > 25:                               // большой отрыв — сброс (строго >)
    E = 0
    R = damping / stiffness
    V = (L - T) / 0.01
    P = T - R·V

Vold = V
Vnew = (V - (damping·dt)·V) + (stiffness·dt)·E
P    = dt·Vnew + P                          // полунеявный Эйлер
V    = Vnew

speed    = sqrt(Vnew·Vnew)                  // x87; сумма X, Y, Z по порядку
spinInc  = (speed / spinDivisor) · dt
yaw      = atan2(Vnew.x, Vnew.z)            // x87 FPATAN
roll     = 0
oldSpeed = sqrt(Vold·Vold)

if speed != 0 and oldSpeed != 0:
    cross = Vnew.x·Vold.z - Vnew.z·Vold.x
    sign  = cross < 0 ? -1 : +1
    c     = clamp((Vnew/speed)·(Vold/oldSpeed), -1, 1)
    angle = acos(c)                         // x87: atan2(sqrt(1 - c²), c)
    roll  = ((((angle·sign)·speed)·bankGain) / dt) · 0.001

spin += spinInc
T.xyz = P.xyz
```

## Точность

Результат зависит от порядка операций и x87-хелперов:
- `sqrt`, `atan2`, `acos` — хелперы `0x408640`, `0x408634`, `0x408620`. Результат округляется до float32 при `FSTP`; библиотечные функции могут дать другой последний бит.
- Скорости сначала нормируются покомпонентно, потом перемножаются. Это не то же, что `dot / (speed·oldSpeed)`.
- `damping·dt·V` вычитается отдельно, а не как `(1 - damping·dt)·V`.
